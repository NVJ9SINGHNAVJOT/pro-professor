# Frontend Folder Structure & Conventions

Architectural patterns for the `frontend/` React app. When adding new features or modifying
existing code, adhere to these conventions to maintain consistency. (The backend's equivalent
lives in [backend/central-server/docs/folder-structure.md](../../backend/central-server/docs/folder-structure.md);
system-level flows live in [docs/project-flow.md](../../docs/project-flow.md).)

The frontend uses a **Feature Module** architecture. While global utilities and UI components
live at the top level of `src/`, feature-specific code is encapsulated inside its own module
directory.

## Module Structure (`src/modules/<feature-name>/`)

When building a new feature or major route area, encapsulate it inside
`src/modules/<feature-name>/`. Every module can contain the following subdirectories as needed:

```
src/modules/<feature-name>/
├── components/          # UI Components that are ONLY used within this feature.
│                        # (If a component is shared across multiple modules, move it to src/components/common/)
├── hooks/               # Custom React hooks specific to this feature.
├── screens/             # Top-level layout components that combine smaller components to form a full page view.
├── utils/               # Helper functions and business logic specific to this feature.
├── validations/         # Zod schemas or validation logic specific to forms in this feature.
├── types/               # TypeScript interfaces and types specific to this feature.
└── constants/           # Feature-specific constants (e.g., dropdown options, specific UI strings).
```

> Modules with a domain layer may add more (the diagram module has `model/`, `commands/`,
> `schema/`, `adapter/`, `renderer/`, … — see [docs/diagram-flow.md](../../docs/diagram-flow.md)).
> The subfolder names above are the shared baseline.

## Global Structure (`src/`)

Code that is shared across multiple modules belongs at the top level of `src/`:

```
src/
├── components/
│   ├── common/          # Reusable UI components (buttons, navbars, modals)
│   └── ui/              # Base UI components (often generated by Radix/shadcn)
├── constants/           # Global constants (e.g., application-wide routes, configuration flags)
├── context/             # Global React Context providers (e.g., SocketProvider, AuthProvider)
├── hooks/               # Custom React hooks used across multiple features (e.g., useApi)
├── modules/             # [Feature Modules - see above]
├── pages/               # Top-level route components that render specific Module Screens and inject global context.
├── redux/               # Global state management (store setup, global slices)
├── services/            # API route definitions and network utility wrappers (e.g., fetch setup)
├── socket/              # Global WebSocket configuration and event definitions
├── styles/              # Global CSS files and Tailwind configurations
├── types/               # Global TypeScript definitions used across the entire app
└── utils/               # Global helper functions (e.g., tailwind `cn` merger, date formatters)
```

## Key Frontend Rules

1. **Module Encapsulation**: A module should not import from another module's internal folders.
   If feature A needs something from feature B, that code should probably be moved to a global
   folder like `src/components/common` or `src/utils`.
2. **Screens vs Pages**: `modules/*/screens/` handle the complex UI layout of a feature.
   `src/pages/` are thin wrappers that connect those screens to the application router and
   global state if needed.
3. **Desktop-Only Target**: This application is strictly for desktop resolutions. Do not use
   mobile-first responsive utilities unless explicitly needed for a specific desktop layout.
   To enforce the minimum width, use the `.min-w-minContent` class on main wrappers, which sets
   `min-width: var(--spacing-minContent) /* 1024px */;`.
4. **Absolute Imports**: Always use global absolute imports (e.g., `@/modules/chat/types`)
   rather than relative paths (e.g., `../types`), even when importing between files within the
   same module.
